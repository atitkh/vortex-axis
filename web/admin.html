    Reset

    Returns the device to how it was before it was set up: it forgets its pairing, its settings and any wake word it was sent, and it is removed here. Its firmware stays. With Wi-Fi forgotten too it comes back as its own setup network; otherwise it stays on the Wi-Fi and waits for a setup string.

    Firmware

    Axis keeps the last five builds of each client type. One of them is the one devices are sent. A device installs it in its spare slot, restarts, and goes back to its old firmware by itself if the new one cannot reach Axis. To go back to an older build, make it the one that is sent and update the devices again.

    Add a build

    The type the firmware reports, not a display name. A build only ever goes to devices of its own type.

    firmware.bin from the build folder. It becomes the build devices are sent; nothing is updated until you say so below.

    Face

    Every look the vortex face has, drawn by the same code the web client uses. The boards draw the same looks from the same numbers. Idle looks are picked at random while nothing is happening; state looks follow what a device is doing.

    Idle looks

    Untick a look to take it out of what devices drift through when idle. It applies to every device, a few seconds after the change. One look always stays on.

    State looks

    One for each thing a device can be doing. The last two are thinking with the agent's run held up, which only an OpenClaw agent reports.

    Tool icons

    While it thinks, the face can show what kind of tool the agent has picked up. Choose how, for every device; it applies a few seconds after the change. Each kind is drawn below as the devices will show it. Only an OpenClaw agent says which tools it uses.

    Wake words

    The phrases a device can listen for. Every device has one built into its firmware. The ones stored here can be chosen in its place, for all devices, a type or one device, with the Wake word setting. A device fetches the model it is given, keeps it and restarts to use it; if the model will not load it goes back to its built-in one. There is no history: uploading a phrase that is already here replaces it.

    What devices heard

    Every wake word a device reported: how sure it was and what came of it. Scores bunched just above the cutoff mean the cutoff is doing real work; scores far above it leave room to raise it against false wakes. A device only reports a wake that passed its cutoff, so near misses are not here; those are in the device's own log.

    Add a wake word

    A microWakeWord streaming model (.tflite) with a 10 ms feature step.

    Optional. The .json that came with the model; it fills in the three fields below.

    How sure the model must be, in percent. Lower wakes more easily, and more often by mistake. A device's own Wake word cutoff setting overrides it.

    How many of the model's answers are averaged. Use the manifest's value unless you know better.

    Agent

    Who answers when someone talks to a client.

    Added to the agent's own system prompt on every turn from Axis: that it is speaking as a voice assistant, what the line describing the device means, and that the Axis tools reach the devices. Keep it free of anything that changes from turn to turn. Empty the box and save for the built-in one; a single - sends none.

    Sent with every turn, ahead of the person's words. It tells the model it is a voice assistant and how to read the line that describes the device. Empty the box and save to go back to the built-in one. An OpenClaw agent has its own prompt and is not sent this.

    Sends one short message with what is typed above. Nothing is saved.

    Agent tools

    What an agent can do through Axis. The same tools reach an agent two ways: the OpenClaw gateway gets them through the node link, and any other harness gets them by MCP, connecting to the address below with a token made here. Who answers when somebody speaks is a separate matter, on the Agent page.

    Tools

    A tool switched off is taken from every agent at once, by both ways in.

    OpenClaw progress cards

    An agent on the linked OpenClaw gateway keeps a list of steps for long work. With this on, Axis shows it on the screens with no tool call: named after where you talk to the agent, waiting for you when the agent has stopped with steps left, done when every step is. Scheduled jobs are left out. An agent on anything else reports with the progress tool.

    OpenClaw questions and approvals

    When an agent on the gateway asks you something, the device you last used shows it and says it, with the choices to tap or to say. While Home Assistant says you are away it goes to your phone as a notification. It can still be answered wherever else it appears; the first answer counts. A secret is never asked for here.

    When an agent needs your leave to run a command or use a tool, a device with a screen shows what it is, silently, with Allow once and Deny. Only a tap allows; a voice can only refuse. A standing permission is never given from here.

    Connect a harness by MCP

    Give the harness this as a remote MCP server ("streamable HTTP") with a token below as its Bearer token. It is the address you are using this page at; a harness on another machine needs a name it can reach Axis by.

    The shape most harnesses take. Put a token in place of YOUR_TOKEN.

    Tokens

    Realtime voice

    A second way to answer what is said, in place of the recognition and the voice above. What a device hears goes through the OpenClaw gateway to a realtime voice model, which answers in its own voice and hands real work to the agent. It is quicker for small things and sounds more like talk. The sound leaves this network for the provider, who may charge for it, and a person cannot talk over the answer.

    The realtime voices the gateway offers. "Try it" opens a session and closes it again: the gateway lists a voice before its credentials have been tried, so this is how to know one works.
