# Native macOS desktop app: scoping

Status: **proposal / audit**, written 2026-10-19 from the code at the commit named in `CLAUDE.md` Status (Axis 0.46.0, desktop app 0.10.4, protocol 1). Nothing here was compiled or run: this host is Linux with no Swift toolchain and no macOS. Every API claim about macOS comes from general knowledge of the platform, not from this repository, and is marked **(unverified)** where a wrong guess would cost a day. Claims about the Windows app are read straight from the source and cited as `file:line`; paths are relative to `clients/windows-desktop/` unless they start with `server/` or `protocol/`.

The plan stated in `CLAUDE.md` is "reuse `Axis.Desktop.Core`, write the platform part". Because the target is native Swift, "reuse" means **port Core line for line, keep the wire behaviour byte-compatible, and replace the platform part**. Section 1 says how much of Core is really portable as logic; section 2 is the contract; section 3 maps the platform half; sections 4 and 5 are layout, milestones, size and risk.

Windows facts used for sizing (from `wc -l`): `Axis.Desktop.Core` 2,065 lines (DesktopCommands 915, Voice 349, AxisLink 308, Face 209, Geometry 79, AppUpdate 70, FaceIcons.g 68, AxisAddress 67); `VortexDesktop` about 3,770 lines of C# and XAML (App.xaml.cs 1,050, ScreenReader 335, FaceWindow 294, Windows 236, Input 208, VoiceIo 204, Overlay 146 plus its XAML, the pills, Saved, Uia, Native, Diag); `Axis.Desktop.Smoke` 213 (13 checks in `Checks.cs`).

## 1. Axis.Desktop.Core: what is neutral and what quietly assumes Windows

Core has no Windows API calls (`Axis.Desktop.Core.csproj:2` says so, and the smoke test runs it on Linux). Nothing in it needs rewriting for a different OS *as logic*. What does need attention is behaviour baked in as constants, vocabulary and strings.

### 1.2 Quietly Windows-assuming, inside Core

These are the things that would be silently wrong, not compile errors, if Core were copied as is.

1. **Client type string** `windows-desktop` at `DesktopCommands.cs:872`. The server also hard-codes it: `server/src/desktopapp.ts:7` and the update download at `server/src/http.ts:520` (`client.type !== DESKTOP_TYPE` gives 404). A Mac needs its own type (suggest `macos-desktop`). Everything else on the server keys on the **capability** `desktop`, not the type (`server/src/desktop.ts:173` `online()`; `:185`), and a repo-wide grep found no other use of the string outside docs and build scripts. Not verified: admin page UI that might show a type label (the grep covered `server/src` and docs only, not `web/`).
2. **Element `Kind` vocabulary is UI Automation's ControlType names, lower-cased.** It is produced in `VortexDesktop/ScreenReader.cs:282-286` and then consumed by Core as a closed set: `Actionable` at `DesktopCommands.cs:790-794` (`button, edit, hyperlink, menuitem, checkbox, radiobutton, combobox, tabitem, listitem, treeitem, slider, spinner, splitbutton, menubaritem, dataitem, password, document`), the demotion list at `:573` (`window, pane, group, document, titlebar`), `Pick` ranking at `:812-814`, password refusals at `:654` and `:727` (`Kind == "password"`), the click guard `Geometry.ChromeRefusal` (`inPage` comes from `document`), and the match bonus `e.Kind == kind` at `:572` (agents pass `kind` such as `button`, `edit`). A Mac reader must **emit this same vocabulary**; table in 3.2. The server also depends on the shape: it parses lines with `^(\d+) \S+ (-?\d+),(-?\d+) (\d+)x(\d+) ?(.*)$` (`server/src/desktop.ts:456`), so a `kind` containing a space would break risk detection. Kinds must be single tokens with no whitespace.
3. **"App" is a Windows process name.** `WindowInfo.App` comes from `Process.ProcessName`, no `.exe` (`ScreenReader.cs:252`). `Geometry.IsBrowser` (`Geometry.cs:61-65`) matches that against `chrome, msedge, firefox, brave, ...` and strips `.exe`. On macOS the natural value is `NSRunningApplication.localizedName` ("Google Chrome", "Safari", "Microsoft Edge"), which would never match this list, so the browser-chrome click guard would silently never fire. The block list also matches `"{title} {app}"` as a substring (`DesktopCommands.cs:236`), so what string the Mac sends as `app` decides whether entries like `keepass` or `1password` match. Decide one: recommend `localizedName`, and extend `IsBrowser` to compare a normalised form (lower-case, spaces removed, "google" prefix dropped) plus Safari.
4. **Key vocabulary and the meaning of "ctrl".** `KeyCombo` (`DesktopCommands.cs:109-165`) has Ctrl, Alt, Shift and *Win*; `cmd`, `meta`, `super`, `windows` all collapse to Win (`:137`). On a Mac, cmd is the primary shortcut modifier: an agent that has learned "ctrl+s saves", "ctrl+c copies" (the tool description, `server/src/commands.ts:229`, says `keys (one combo: enter, ctrl+s)`) will press Control+S, which does nothing useful. Decision needed (section 5): either keep literal modifiers and teach the agent via the tool text, or map `ctrl` to cmd for the "copy-class" shortcuts. Recommendation: add a distinct `Cmd` field to `KeyCombo` (and keep `win`/`meta`/`super` as cmd on Mac), do **not** silently rewrite ctrl, and make the Mac `describe` and the tool description say "cmd+s". Not decided by the owner.
5. **Blocked chords are Windows chords** (`KeyCombo.Blocked`, `DesktopCommands.cs:153-161`: Win+L, Ctrl+Alt+Delete/End, Ctrl+Shift+Escape, Alt+F4, Win+X/R). The Mac set must be rewritten; suggested minimum: cmd+ctrl+q (lock), cmd+shift+q and cmd+opt+shift+q (log out), cmd+opt+esc (Force Quit), cmd+q and cmd+w (the Alt+F4 rule is "closing the window"), cmd+opt+ctrl+power/eject variants, cmd+space (opens Spotlight; not dangerous, optional), ctrl+cmd+power. The user-facing help text at `:882` also names "lock, sign-out, Task Manager or Alt+F4" and must change.
6. **Named keys include Windows-only and media keys** (`:113-116`: `printscreen`, `menu`, `volumeup/down/mute`, `mediaplaypause/next/previous/stop`). On macOS media and volume keys are not ordinary key events; they are `NSSystemDefined` events with `NX_KEYTYPE_*` subtype 8 **(unverified)**. `F1`..`F24` is accepted (`:144`) but a Mac keyboard layer tops out around F20. `printscreen` has no key; the equivalent is cmd+shift+3, so refuse it or alias it. `insert` and `menu` do not exist on Mac keyboards.
7. **Unicode characters are validated as printable ASCII only** for single keys (`key[0] is >= ' ' and <= '~'`, `:143`). Fine for chords; `type` is not affected (it sends arbitrary text).
8. **Platform strings in Core**: "Start menu" in `IDesktop.OpenAsync` doc (`:77`), `desktop.open` error text (`:679`), the setting help for `allowInput` (`:882`). `DesktopCommands.cs:223` and `AxisLink.cs:250` format an `HResult` (`0x{e.HResult:X8}`) for errors with no message; on Swift report the `NSError` domain and code instead.
9. **`Busy()` reads the .NET thread pool** (`DesktopCommands.cs:377-381`, called from `AxisLink.cs:241,263`). Diagnostic only; replace with a task/queue depth or drop. The reason it exists (0.4.0, a starved pool) is a .NET artefact.
10. **Coordinates are "physical pixels, top-left origin, negative to the left/above of the main display"** (`:21`, `:34-38`, `LookData` at `:845`). On macOS the equivalent unit is the **point**, not the pixel; see 3.3. Several constants are in that unit and will be wrong in a Retina world if copied blindly: `Geometry.MinSide` 40, `ChromeBand` 100 (`Geometry.cs:31-35`), pointer size 24 to 120 (`:888`).
11. **Window list in a screen look carries only the title.** `ScreenReader.Read` for scope `screen` adds each top-level window as an element whose name is the title (`ScreenReader.cs:131-137`), and the block-list pass over it is called with `app = null` (`DesktopCommands.cs:269`, `:356`). So on Windows, an entry that matches only a *process name* (say `keepass`, whose window title is "Database") does **not** hide the window in a `look screen` or `window list`. This is existing behaviour, not a Mac issue; on Mac the same blind spot exists unless the Mac reader puts the owner name in the element name. Flagged so the Mac port does not copy a gap by accident.
12. **Block list is only checked once per `steps` call on the client.** `BlockedFrontAsync` runs in `HandleAsync` (`:209`) before the whole list; the inner `RunAsync` per step (`:467`) does not re-check the front window after an `open` or `switch` step brings a different app forward. The server does check each step's `app`/`url`/`window` against the list (`server/src/desktop.ts:283`) and strips blocked windows from answers (`:340-352`), so a blocked app reached by a *click* inside a steps batch is not stopped on the client. Existing gap on Windows; decide whether to fix it in both when porting (cheap: re-check front window between steps).
13. **A `Paused` app refuses even `desktop.hello`** (`:256`). Intentional; keep.

### 1.3 Windows-assuming outside Core but inside the "reuse" story

- `VortexDesktop/App.xaml.cs:535-586` the "intended window" logic (type/keys go to the window the agent last opened or switched to; brought back if something stole focus, refused otherwise). It is *behaviour the agent depends on* (the tool text says so, `commands.ts:229`), but it lives in the platform half, so the Mac port must reimplement it. It uses `SameOrOwned` on owner chains (`Windows.cs:118-127`); macOS has no owned-window concept, use "same app and same window, or a sheet/dialog child of it" via AX.
- The `Ref` object on `ScreenElement` (`DesktopCommands.cs:10`) is the platform handle (`AutomationElement`). In Swift it becomes an `AXUIElement`; it is never sent on the wire.
- Per-call UI Automation threads with deadlines (`Uia.cs:13-50`, `MaxStuck` 8). AX calls into a hung app also block, with a default timeout of about six seconds **(unverified)**; plan the same pattern (see 3.1).

## 2. The wire protocol the Mac app must speak

Authoritative sources: `protocol/src/messages.ts`, `protocol/src/common.ts`, `protocol/schema/axis-protocol.v1.json`, `protocol/README.md`, and for the desktop commands `DesktopCommands.cs` plus `server/src/desktop.ts`. This section restates what the Windows app actually does so a Swift client can be written without reading C#.

### 2.1 Pairing (HTTP)

`POST {http-base}/v1/pair`, `Content-Type: application/json`, 15 s timeout (`AxisLink.cs:73-91`).

```json
{ "code": "123-456", "type": "macos-desktop", "version": "0.1.0",
  "capabilities": ["desktop"], "name": "Atit's MacBook" }
```

`name` is omitted when blank. A pairing code is one-time, from the admin page's "Add a device"; the setup string `axis://host:port/<code>` (or `axis+tls://`) carries it (`AxisAddress.Parse`). Success reply: `{ "clientId": "...", "token": "...", "name": "..." }`. On a non-2xx status the message is `reply.error`, else `Axis said <status>.`

Keep `clientId`, `token`, `name` and the address. Windows encrypts the token with DPAPI and stores the rest in `%APPDATA%\VorteX Axis\desktop.json` (`Saved.cs:12-94`). Mac: Keychain for the token, the rest in `~/Library/Application Support/VorteX Axis/desktop.json`. Keep the same JSON field names (`Address, ClientId, Name, Paused, Voice, ShowControl, ShowFace, KeepFace, TalkKey, MicDevice, SpeakerDevice, FaceSize, FacePlace, FaceX, FaceY`) so the Core settings model stays shared; drop `TokenProtected`.

### 2.2 The encrypted link

There is **no application-layer encryption or signing** in this protocol. "Encrypted" means **TLS**: an `https://` or `axis+tls://` address yields `wss://` and `https://` calls; a plain `host:port` yields `ws://` and `http://` (a LAN hub). The token travels in the `hello` frame, so plain `ws` is acceptable only on a trusted network. Rule to keep: update downloads are refused over plain http unless the host is this computer, RFC1918/link-local/ULA, a tailnet (100.64.0.0/10), `.local`, `.lan`, `.home.arpa`, `.ts.net` or a dotless name (`AppUpdate.cs:26-37, 45`).

macOS App Transport Security blocks plain `http://`/`ws://` to non-local hosts by default, and treats local-network hosts differently depending on keys in `Info.plist` **(unverified)**. Set `NSAppTransportSecurity` / `NSAllowsLocalNetworking` (and `NSLocalNetworkUsageDescription`, since macOS 15 prompts for Local Network access **(unverified)**) or the LAN case will fail with an ATS error that looks like a hub being down.

### 2.3 Connection and handshake (WebSocket `/v1/client`)

1. Open `ws(s)://host[:port]/v1/client`.
2. Client sends **hello** (first frame), text JSON:
   ```json
   { "t":"hello", "protocol":1, "clientId":"…", "token":"…", "type":"macos-desktop",
     "version":"0.1.0", "capabilities":["desktop"], "settingsVersion":0,
     "maxFrameBytes":65536, "audioBufferMs":8000 }
   ```
   `audioBufferMs` only when the app has a speaker (Windows: 8000, `App.xaml.cs:175`; schema min 200, max 60000). `maxFrameBytes` is the biggest *binary* frame the client accepts (schema 512 to 1,048,576, default 4096); the Windows app says 65536. Capabilities: `["desktop"]`, plus `["mic","speaker","screen"]` when voice is on (`DesktopCommands.cs:878`). `screen` means "I can show Axis's questions"; this is what makes the server ask `confirmRisky` questions *on the computer itself* (`server/src/desktop.ts:398`), so advertising it obliges the app to implement the `ask` pill.
3. Axis replies **welcome**: `{t:"welcome", protocol, clientId, serverTime(ms), settingsVersion}`. On `welcome` the client immediately sends **describe** and goes Online (`AxisLink.cs:193-196`).
4. Axis sends **settings**: `{t:"settings", version:N, values:{key: scalar}}` (full resolved set: global then client type then device). Keep `version`, send it back as `settingsVersion` on the next hello.
5. Reconnect after any drop: 1, 2, 5, 10, 30 s then stay at 30 s; reset the counter after a connection that completed a session (`AxisLink.cs:121-142`). Stop for good (state `Refused`) on `error` with code `unauthorized` (pairing is gone: pair again) or `unsupported_protocol`, or a close whose description contains "token" (`:221-233`).

**describe** (client to Axis) is `{t:"describe", settings:[…≤48], actions:[…≤24], links:[…≤8]}` and Axis keeps it per client type. Settings entries are `{key,label,kind:"toggle"|"number",group,help,default}` (number adds `min,max,unit`). Windows defaults are sent as **strings** `"1"`/`"0"` for toggles and the number 44 for `pointerSize`. The eight settings (`DesktopCommands.cs:880-888`):

| key | default | read by | meaning |
|---|---|---|---|
| `allowLook` | 1 | client | off refuses look, find, clipboard, window list |
| `allowInput` | 1 | client **and** server | off refuses click/drag/type/keys/open/switch/window/desktop/scroll/paste/steps; looking and pointing continue |
| `bubble` | 1 | client | show the agent's words beside the pointer |
| `allowScreenshot` | **0** | client **and** server | off refuses `desktop.screenshot` |
| `autoUpdate` | 1 | server | server only offers `update` when on (`desktopapp.ts:124`) |
| `confirmRisky` | 1 | **server only** | server asks Allow/Deny before risky clicks/Enter; the client does nothing for it except being able to show the question |
| `autoOcr` | 1 | client | read pixels when a window exposes fewer than 8 named controls |
| `pointerSize` | 44 (24 to 120, px) | client | pointer size |

One action: `{name:"desktop.hello", label:"Show the pointer", help:"…"}`. The client reads toggles leniently: true/false, number nonzero, or string `"1"`/`"true"` (`Toggle`, `:195-203`). Missing key uses the default in the table.

### 2.4 Frames, sizes and timeouts

- JSON text frames, UTF-8, one message per frame. Binary frames are raw audio only (below).
- A `command` has `{t:"command", id, name, params?, data?}`. `params` values are **scalars only**, strings at most 512 characters, keys at most 64 characters (`protocol/src/common.ts:46-57`, `messages.ts:342`). `data` is any JSON and is used for what does not fit (`desktop.steps` steps, `desktop.paste` text). **The Windows client folds `data` into `params.data` before dispatch** (`AxisLink.cs:209-214`); do the same, or hand handlers the `data` separately, but keep the handler contract "paste text is in `params.text` or `params.data.text`; steps are in `params.data.steps`" (`DesktopCommands.cs:722`, `:453`).
- The reply is `{t:"command.result", id, ok, payload?, data?, error?}`. `payload` is a flat map of scalars (≤64-char keys, ≤512-char strings); `data` is any JSON. `error` is cut to 256 characters (client sends first 255 plus "…", `AxisLink.cs:257`). The connection's JSON frame limit is documented as 1 MB (`messages.ts:195-197`); a screenshot's base64 must stay well under that. Not verified: where the server enforces it.
- Axis-side timeouts you must beat (`server/src/desktop.ts:36-39,300,323`): look/find/screenshot 15 s, point/hide/clipboard 5 s, other actions 15 s, `wait` = seconds + 5 s, `steps` 60 s, `update` 120 s. The Windows client answers a look/find/screenshot itself after **12 s** with a failure so the agent hears why (`DesktopCommands.cs:390-399`). Do the same. Also report (do not send to Axis) any command that waited more than 1 s to start or took more than 10 s to answer (`AxisLink.cs:241,262`).
- Messages the Mac app must at least tolerate from Axis: `turn, transcript, reply.text, speak.start, speak.end, stop, ask, ask.end, status, error`; unknown types are ignored (`AxisLink.cs:218-226`). Messages it sends when voice is on: `audio.start, audio.end, playback, interrupt, answer`.

`ok:false` with `error` for any failure. Successful answers use `payload` (scalars) and/or `data` (structured), as listed. Commands in the "changes" set (click, drag, type, keys, open, switch, window, desktop, steps, scroll, paste) additionally get `data.after` appended, see 2.7.

### 2.6 The look object and ScreenElement

`ScreenElement(Kind, Name, X, Y, W, H, Value, Focused, Source)` (`DesktopCommands.cs:7`): integers in screen units, `Source` is `"ui"` or `"ocr"`, and a non-wire `Ref`.

Elements are sent as **text lines**, not objects (about half the tokens, `:579-590`):

```
<id> <kind> <x>,<y> <w>x<h> <name≤160>[ = <value≤160>][ *focus][ (ocr)]
17 button 1510,-100 60x40 Send
```

`name` is trimmed and clipped with a trailing `…`; `value` only when non-empty; ` *focus` when focused; ` (ocr)` when `Source != "ui"`. The server parses these lines with the regex quoted in 1.2 item 2 and strips ` = …` and ` *…`; do not put ` = ` or ` *word` inside names without expecting that. `id` is the 1-based position in the list sent.

`data` for `desktop.look` (`LookData`, `:825-858`):

```json
{ "screen": "-1440,0 4000x1440",        // x,y wxh of the whole virtual desktop
  "mouse":  "812,640",
  "window": "Inbox - Mail (outlook) 0,0 1200x800",   // title clipped 200, then (app), then box
  "monitors": ["0,0 2560x1440 main", "-1440,0 1440x900"],
  "underMouse": 12,                       // id of the smallest element containing the mouse
  "elements": ["1 window 0,0 1200x800 Inbox - Mail", "2 button …"],
  "more": 37,                             // present when the list was cut to 250
  "ocr": "…"                              // note, only when OCR ran or failed
}
```

Per scope:

- `window` (default): the window in front, its controls (up to 1,500 collected, `ScreenReader.cs:32`), plus any popup menus above it **listed first** so context-menu items are clickable by name right after a right-click (`:162-173`). Offscreen, tiny (under 2x2), and unnamed containers are dropped; a field is kept even unnamed (`:258-279`, rule at `:274`).
- `mouse`: the element under the mouse, its children, and up to four ancestors; OCR area is the mouse point inflated by 300 x 120.
- `screen`: top-level windows only, each as `kind window`, name = title. No OCR (`:86`).

Selection to the 250-element cap (`Pick`, `:801-823`): keep everything if ≤250; otherwise rank 0 = first element, any `window`, the focused one, and an *actionable* one holding the mouse; rank 1 = other actionable; rank 2 = the rest; within rank nearest the mouse first, then list order; finally restore list order. `MaxElements` = 250.

OCR: automatic when OCR is `Auto` and fewer than **8** elements have a non-empty name and a kind outside `window, pane, group` (`SparseBelow`, `:34,85`), and scope is not `screen`. Lines of OCR text become `kind text`, `Source ocr`, no `Ref`. Read gets 10 s, OCR 4 s (`:35-36`); on OCR trouble the look still succeeds with `ocr: "text from the pixels skipped: <why>"`.

### 2.7 Ids, staleness, "after"

- Ids are positions in the **last look or find**; the table is replaced by every `look`, every `find`, every by-name action (`TargetAsync` does a `FreshLookAsync`, `:507`, `:490-495`), and a `look` clears the scrolled flag. A by-name tie failure lists ids ("`id 5: button "Send"; …`") and says they hold for the next call (`:514-515`), which is true because the fresh look just set them.
- **Stale-after-scroll**: `desktop.scroll` sets `scrolled = true` (`:713`). Then using an id (`ByIdAsync`, `:526-536`): if the element has a `Ref`, it is re-read and its box cut to what shows; if it is off screen now the answer is `element N is off the screen since the scroll; look again`; if it has **no `Ref` (OCR text)** the answer is `scrolled since the last look, so element N may have moved; look again`. A name or x,y is not affected.
- **`after`** (`WithAfterAsync`, `:418-438`): for every command in the changes set the client takes the window-in-front and focus state *before* (`StateAsync`), runs the command, waits **300 ms** (**400 ms** if the command is `open` or a `steps` containing `open`), reads the state again, and adds to `data`:
  ```json
  "after": { "window": "Title (app)", "new": true, "focus": "edit Search", "value": "hello" }
  ```
  `new` only when title or app changed; `focus` = `"<kind> <name≤80>"`; `value` ≤120. If reading state fails or times out (focus read gets 1.5 s, `ScreenReader.cs:38`), the answer goes without it. Server code and agents rely on it so they need not look again.

### 2.8 Geometry clipping and click behaviour

`Geometry` rules (`Geometry.cs`):

- A control's visible part = its box intersected with **every enclosing `document` (web page) box and finally its own top-level window** (`ScreenReader.Where`, `:216-238`, `Geometry.Visible`). Parent walk depth ≤60 (`MaxDepth`).
- During a look, controls that cross a page's edge are cut to the visible part, or dropped if nothing shows; at most **40** such re-reads per look (`MaxClipped`, `:46,191-213`). Controls wholly in or out of every page are left as read.
- `Enough(box, visible)` = `Fraction ≥ 0.4` **or** the visible piece is at least **40 x 40** (`MinVisible`, `MinSide`).
- Click on a target (with `Ref`): re-locate it **now** and aim at the centre of what shows, not where the look saw it (`App.xaml.cs:620-625`). Then in order:
  1. left click and the control offers a direct action: do it with no mouse (`how:"invoked"`); a timeout here counts as invoked (a dialog may block the call, `:637`);
  2. kind `edit`/`combobox` and it can take focus: focus it (`how:"focused"`);
  3. if not `Enough` visible: scroll it into view, re-read; still not enough fails with `only N% of "<name>" shows … scroll until it shows, look again, then click`;
  4. `Geometry.ChromeRefusal`: if the front window is a browser, the click is on a control inside a page, and `y` lies within the top **100** px of the window (`ChromeBand`), it is refused unless the page itself starts at the top of the window (`page.Y >= window.Y - 2 && y >= page.Y`), message: *"that spot is on the browser's own bar at the top of the window, not the page; scroll up a little so it comes down into the page, look again, and click it there"* (`Geometry.cs:73-78`). A bare `x,y` and non-page controls are never refused;
  5. real mouse click, mouse put back (`how:"mouse"`).
  The pointer is shown and given time to glide (220 ms plus 30) before acting (`App.xaml.cs:602-606`), and 150 ms after, the "intended window" is re-recorded.
- Typing/pasting into a target focuses it first; with no target, the "intended window" is brought back to the front or nothing is typed (`App.xaml.cs:576-586`, 90 s memory `IntendedFor`).

### 2.9 Block list, allow switches, passwords, confirmation

- **Block list** (`DesktopCommands.cs:229-252`). `blocked` = `|`-joined lower-case substrings, each 2 to 40 chars with no `|`, from the admin page (`server/src/hubconfig.ts:200-205`, up to `MAX_BLOCKED`). Client rule: for every `desktop.*` command **except** `hello, hide, open, switch, window`, and except `look` with `scope=screen`, read the window in front; if `lower("{title} {app}")` contains any entry, answer `ok:false`: *"the window in front is blocked by the user (it matches \"X\"): the app neither reads it nor acts on it. Tell the person; do not try another way"*. In a `scope=screen` look and in `window list`, a window whose title matches is replaced by `Name="blocked by the user"`, `Value=null`, no `Ref`. The server independently refuses calls that *name* a blocked app/url/window and blanks blocked windows in any answer (`desktop.ts:232-233, 340-352`), so the client's check is the backstop for what only the computer can see (which window is actually in front).
- **`allowLook`** (checked in look, find, clipboard, window list), **`allowInput`** (checked in `ActAsync` for the whole input group, `:595`), **`allowScreenshot`** (screenshot). The server also refuses input when the setting is off or when a scheduled task was not permitted to act (`mayChange`, `desktop.ts:414-421`, `Desktops.holdLookOnly`).
- **Pause**: while the person has paused the app, every `desktop.*` command (hello included) fails with *"the person at the computer has paused the VorteX Axis desktop app"* (`:256`). The pause persists in `Saved.Paused`.
- **Password fields**: the reader never reads a secure field's value and reports its kind as `password` (`ScreenReader.cs:270`). `type` and `paste` refuse a target of kind `password` (`:654, :727`) *and* refuse when the **focused** element is a password field even if the target is another (`App.xaml.cs:759-775`). Screenshot is refused when the focused element is a password field, or when that cannot be determined within 1.5 s (`:871-875`). All three rules must be kept; they are the app's own safety, not Axis's.
- **`confirmRisky`** is entirely **server side**: `server/src/desktop.ts:366-411` decides "risky" from the element *name* (whole-word match against send, post, publish, submit, delete, remove, buy, purchase, pay, order, confirm, transfer, sign out, log out, uninstall, format, erase, reset, install, accept: `server/src/risky.ts:9-12`) or, in a "sending" window (title contains mail, inbox, chat, discord, slack, teams, bank, checkout, payment, wallet…), Enter/ctrl+Enter and text containing a newline. It asks `Allow`/`Deny` with a 30 s timeout via `hub.ask`, **on the computer if it advertises `mic` or `screen`**, else on a nearby device. The client's job: show the `ask` question and its choices and answer `{t:"answer", askId, choice}` (`Voice.cs:117-131`, `ask`/`ask.end` at `:317-331`). The word lists are English-only and Windows-centric only mildly (they match element names); they are shared and need no Mac change. The `confirmed` string is added to the answer by the server.
- Key blocks: `KeyCombo.Blocked()` (1.2 item 5).

### 2.10 Voice (optional capability set `mic`, `speaker`, `screen`)

Sent: `audio.start {turnId, format:{encoding:"pcm_s16le", sampleRate:16000, channels:1}, trigger:"tap"|"hold"|"question"}`, then binary frames of 16 kHz mono 16-bit little-endian PCM (about 20 ms each), then `audio.end {turnId, reason:"silence"|"max"|"cancel"}`. Turn ids are `pc-<hex ms>-<n>` (`Voice.cs:152`). Received: `turn {turnId,state:listening|transcribing|thinking|speaking|idle|error, doing?, detail?}`, `transcript {text}`, `reply.text {turnId,text,final?}`, `speak.start {turnId, format:{sampleRate}}` (default 24000 if absent), binary PCM until `speak.end {turnId}`, `stop`, `ask {askId,question,choices}`, `ask.end {askId}`. Sent back: `playback {turnId,state:"started"|"finished"|"stopped"}`, `interrupt`, `answer {askId,choice}`. All of that is in `Voice.cs` and ports as is; only `IVoiceIo` is platform work.

### 2.11 Update protocol

Axis sends `update {version,size,sha256,path}` (path `/v1/desktop/app`), the client downloads with its token, verifies size and SHA-256, swaps the running program, **answers first**, then restarts (`App.xaml.cs:249-282`: the `.exe` is renamed `.old`, the new file moved in, `{version}` returned, 1.5 s later the new process is started with `--tray --updated` and the old one quits; the new one waits up to 20 s on the single-instance mutex and deletes the `.old`). Axis offers it on connect (1 s after) and every 5 minutes when the connected version is older and `autoUpdate` is not off; it remembers the version it offered each computer so a refusing client is not asked again (`desktopapp.ts:94-135`). Server-side the build is **one file** `desktop/VortexAxisDesktop.exe` with `version.json` in the data folder (`:71-78`), served raw. A Mac needs: a second build slot (for example `desktop-macos/` with a `.zip` of the `.app` and `version.json`), `DESKTOP_TYPE`-per-platform logic in `desktopapp.ts` and `http.ts:516-526`, and a different swap procedure (section 3.7).

### 5.2 Top risks, most serious first

1. **No compile loop on this host.** Mitigation: Core as a pure-Foundation target compiled and tested in a Swift container on Linux (needs the owner's agreement to add that toolchain; not verified to work with `URLSessionWebSocketTask` on Linux); a second option is a Mac-hosted CI runner for the Gitea instance (none exists). Platform code stays Mac-only and is verified by the owner on the Mac.
2. **The AX tree is not UI Automation.** Slower (many IPC round trips), different shape per toolkit, web content in Chrome/Electron may be absent until the accessibility flag is set, no `IsOffscreen`, context menus are not separate windows. The Windows app already needed several fixes for hung or slow UIA (0.4.0 to 0.4.3, `Uia.cs`); expect the same class of problem here with less caching help. The vocabulary mapping in 3.2 decides whether Core's ranking and guards behave.
3. **Permissions and signing identity.** Accessibility, Screen Recording and Microphone are tied to the signing identity; self-updates and ad-hoc rebuilds can silently drop them, leaving a running app that returns empty looks. Requires a stable Developer ID, hardened runtime, notarisation, install location rules. The owner may not have an Apple Developer account (not known).
4. **Activation and input semantics differ.** macOS 14 cooperative activation may stop the app bringing another app forward; synthetic key events interact with keyboard layouts (key codes), Secure Event Input, and apps that ignore Unicode-string events; double click needs click state; drag needs `leftMouseDragged`. The "intended window" guarantee (type goes where the agent was working) rests on reliable activation.
5. **Agent-facing semantics change.** `ctrl` versus `cmd`, `maximize`, `Start-menu app`, blocked chords, media keys, `desktop next` all differ; the tool description is shared (`server/src/commands.ts:222-250`) and says "Start-menu name" and "ctrl+s". Needs a per-platform note in the tool text or the answer (for example the computer's `describe` could carry a short platform hint), or agents will misuse it. Decision for the owner (see 6).
6. **Coordinate and scale bugs** are the classic silent failure: one wrong flip puts clicks on the wrong monitor. Use one conversion function, test with stacked and side-by-side displays at different scales.
7. **The Windows behaviour being copied is partly unproven.** CLAUDE.md "Never run by its author" lists 0.10.0's mouse drag, context-menu reads, the block list and 0.10.4's click cut as unverified by the author (the owner confirmed on 2026-10-13 that the desktop actions worked up to that point; that statement is in CLAUDE.md and I did not re-check it). Porting unproven logic means two copies to debug. Prefer the owner trying them on Windows first, or write the Mac port against the documented contract, not the code.
8. **Updates and releases only fit Windows today**: one `.exe` slot, `windows-desktop`-only download route, Linux CI. Needs server work and a manual Mac release step.
9. **Face copies** go from three to four; a drift risk already called out in CLAUDE.md.
10. **ATS / Local Network** prompts can make a perfectly reachable LAN hub look down.

## 7. Adopted patterns (research 2026-10-19)

The owner said "go with defaults" on section 6: client type `macos-desktop`, the same tool; minimum macOS **13** (not 14: OCR needs 14 and says so on 13); `keys` will accept both `ctrl` and `cmd`, with `ctrl` mapped to cmd for the common shortcuts (M2); the layout of 4.1 without the Xcode project (a script wraps the SwiftPM build instead, below); notarisation deferred to M5. No Swift toolchain was added on this host, so nothing below was compiled.

Patterns taken from a public-domain Mac app that already reads and drives the screen ("Bluey", `github.com/rbrown101010/bluey-by-riley`, Unlicense: `Mac/Sources/GooglyMac/ControlsReader.swift`, `ScreenReader.swift`, `ComputerControl.swift`, `scripts/build-mac.sh`), with Peekaboo (`github.com/openclaw/Peekaboo`, MIT) as a reference only; no code copied from Peekaboo.

- **Reader**: the AX tree of the app in front, from its focused window (else its first window), **breadth first** under a **time budget** (0.45 s, `AXReader.budget`) and caps (1,500 kept, 5,000 visited, 400 children a node). The cap of **250** sent stays where it was, in `DesktopCommands.pick`, so `find` still sees the whole list.
- **`AXUIElementSetMessagingTimeout` 0.25 s** on the app and the system-wide element: a hung app costs a quarter second a call, not about six. Reads run on their own queue under the Core's `within` deadline, which never waits for a stuck call (a task group would).
- **`AXManualAccessibility = true`** on the app element before reading, so Electron apps build their tree. Harmless elsewhere.
- **One batched read per element** (`AXUIElementCopyMultipleAttributeValues`: role, subrole, title, description, placeholder, help, position, size, focused); the **value only afterwards** and never for `AXSecureTextField`.
- **Kinds**: role/subrole to the Windows vocabulary, one lower-case token each (`AXKinds.swift`, tested: no kind has a space, the kinds Core's guards key on are reachable). `AXSecureTextField` → `password`, `AXWebArea` → `document` (and only that), `AXPopUpButton` → `combobox`, `AXTabButton` → `tabitem`, rows by their outline/table parent. Unknown roles become their own name, lower case, letters and digits.
- **Label**: the first of title, description, placeholder, help; static text takes its value as its name; a field keeps its value as the value.
- **One element per box** (the control before its own label) and **reading order** (lines of tops within 6 pt, then left to right; `ReadingOrder`), with the window first and any open menu next, as Windows lists popups first.
- **Ids 1..N** in the list sent, as before.
- **Clipping (0.10.4 port)**: `Geometry.swift` is `Geometry.cs` in Swift, checked by `GeometryTests` (every check in `Axis.Desktop.Smoke/Checks.cs` Clipping and ChromeBand). The reader carries the boxes of every enclosing `AXWebArea` **and `AXScrollArea`** plus the window down the walk and cuts each element to them as it goes (no extra calls; macOS has no "offscreen", so scroll areas stand in for it). `IsBrowser` knows the Mac names (Safari, Google Chrome, Brave Browser, Arc, Firefox, Microsoft Edge, ...), normalised, and their bundle ids, and still the Windows process names.
- **Coordinates**: AX, CGEvent, CGWindowList and CGDisplayBounds are all points with the origin at the top left of the main display, y down: the wire's space, used as is. Only AppKit frames (bottom-left, flipped with the main display's height, `Coordinates.appKit`/`topLeft`) and Vision boxes (0-1, bottom-left of the image, `Coordinates.fromVision`) are converted, each in one function with tests (a display above and left of the main one). Retina appears only in captured pictures, which are cropped in pixels and turned back into points before anything leaves them.
- **OCR fallback** under 8 named controls: ScreenCaptureKit `SCScreenshotManager` (macOS 14) of the display under the window, the app's own windows excluded (no hide-and-wait), cropped, Vision `VNRecognizeTextRequest` accurate, a `text` element per line marked `(ocr)`, 4 s limit; **implemented, not a stub**, never run. On macOS 13 or without Screen Recording the look says why it was skipped.
- **Window titles** from CGWindowList (needs Screen Recording), else the focused window's AX title under a 0.5 s limit. A screen look's window names carry the app ("Title (App)"), which closes the gap of 1.2 item 11 on the Mac only.
- **Packaging**: `clients/macos-desktop/scripts/build-mac.sh` builds with SwiftPM, assembles the `.app` in a temporary folder (iCloud folders break codesign), takes the version from `App.swift`, signs with a Developer ID or Apple Development certificate if there is one (so permissions survive rebuilds) else ad hoc, falls back to ad hoc when the certificate is revoked. `App/Info.plist`: `LSUIElement`, `LSMultipleInstancesProhibited`, `NSLocalNetworkUsageDescription`, `NSMicrophoneUsageDescription` (for M3), ATS `NSAllowsLocalNetworking`.
